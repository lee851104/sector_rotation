## 首版資料與範圍

- 行情採 Twelve Data，使用使用者已建立的帳戶，金鑰存入 GitHub Actions Secret `TWELVE_DATA_API_KEY`。不要求在聊天中傳送金鑰。
- 使用日線、拆股調整後收盤價，個股與 SPY 採相同口徑。顯示「價格報酬，不含股息」，不得宣稱總報酬。
- 比較基準為 SPY，所有標題與說明標示「相對 SPY（S&P 500 代理）」；不把 SPY 稱為官方 S&P 500 指數序列。
- 成分股及 GICS sector/sub-industry 名稱取自公開 S&P 500 成分股表，保存來源 URL、取得日期與名單快照。四層名稱、代碼以具版本日期的 GICS 結構對照表建立。無法精確對照者標示未分類，不用 Yahoo 的其他產業分類猜測填入。
- 分析目前成分股，不提供歷史成分股回測。頁面註明「以目前成分股及分類回看」，避免誤認為無存活者偏差的歷史指數。
- 取得至少 600 筆日資料，足以支援 252 交易日比較及輪動圖暖機；新上市或歷史不足者顯示不足，不補零。
- 首版採等權重。缺乏可靠歷史權重，不提供假的市值加權；市值加權按鈕不啟用，旁註需權重資料。等權重是目前資料方案的實作決定，供本規格審閱。
- GICS L1–L4 僅顯示可對照且有成分股的分組，不保證 S&P 500 涵蓋所有細分產業。分類覆蓋率與行情覆蓋率分別顯示。

## 指標定義

1. 個股每日報酬為 P(t)/P(t-1)-1。各組建立每天等權重再平衡的報酬序列，以有效且連續的成分股日報酬平均、逐日複利得到指數 G(t)。缺值不當零；輸出每天有效家數。
2. 期間為 21、63、126、252 個基準交易日。各組期間指數必須達到所需歷史長度，否則回傳 null。
3. 相對報酬 RS = (1+組別報酬)/(1+SPY報酬)-1，不使用兩個百分比直接相減冒充比值。
4. 相對強弱曲線 = 100 × [G(t)/SPY(t)] / [G(起點)/SPY(起點)]，基準水平線 100。初始選中最強與最弱各三組，點排名表可切換。
5. 輪動圖取每週最後有效交易日：Q=G/SPY；RS-Ratio=100×Q/10週Q均值；RS-Momentum=100×RS-Ratio/4週RS-Ratio均值。暖機不足不畫點。不宣稱為商用 JdK 指標。象限以兩軸 100 為界；等於 100 歸入高側。
6. 軌跡期間 1/3/6/12 個月分別取最近約 4/13/26/52 個週觀測，保留有效暖機後的值；可切換起終點箭頭及完整尾跡。
7. 廣度為所選期間有效個股中，價格報酬大於 0 的比例；顯示有效分母。最強/最弱依期間相對報酬排序。個股列表依同期間個股報酬排序。

## 版面與互動

- 頁首：名稱、行情日期、更新時間、資料狀態與覆蓋率、管理者入口。
- 篩選列：分類層級、期間、最少有效成分股數、等權重標示、箭頭/尾跡。
- 主區：左側四象限輪動圖，右側相對 SPY 曲線。穩定產業顏色，工具提示顯示完整名稱及數值；小螢幕改上下排列。
- 次區：最強與最弱產業、旗下個股報酬標籤。
- 排名表：名稱、代碼、有效/總家數、RS 1M/3M/6M/12M、廣度、象限。欄位可排序、選取與曲線連動。
- 頁尾：來源、公式說明、等權重及價格報酬口徑、目前名單回看限制。
- 未取得首份行情時顯示明確的未初始化狀態，不產生虛構數字。更新中仍可看上一份結果。

## 架構

- 前端：輕量 HTML/CSS/JavaScript 與圖表套件，靜態資產部署 Pages。不需要常駐 Python 服務。
- 資料工作：Python 分離成名單/分類、行情取得、品質驗證、指標計算、JSON 輸出模組。只輸出展示需要的分析資料。
- GitHub Actions：同一 workflow 提供 schedule 與 workflow_dispatch。指定 America/New_York 時區，限制同時一份工作，不取消正在進行的更新。自動重試限速/暫時網路失敗，不能無限重試。
- 持久保存最後成功的行情快照與分析檔於受控資料分支；Actions cache 僅加速，不是唯一備份。更新採完整滾動歷史，避免拆股後新舊調整尺度混用。
- 產生及驗證完整成品後，以 Wrangler 一次發布網站與 JSON；不能將中途不完整結果發布。未通過驗證時保留既有網站與成功快照。

## 額度與資料品質

Twelve Data 已查到 Basic 為每分鐘 8 credits、每日 800 credits，time_series 通常每檔 1 credit。全量約 500 檔加 SPY 至少一小時；採節流並為重試留餘裕，workflow timeout 設足夠長，不承諾免費 Actions 分鐘數永遠足夠。

每天自動一次。手動更新同樣遵守總預算：已在執行則返回既有進度；當日已成功全量更新則返回「今日已更新」而不重新抓全量；失敗後重試只補可重用同次快照中的缺項。提供日期分界、呼叫數與剩餘預算紀錄，配額不足明確回報。

SPY 必須有有效且日期有序的資料；剔除尚未收盤的當日日線。個股日期與基準對齊；行情覆蓋至少 98% 且無日期倒退才發布。缺失股票逐一列出，群組依有效數量重新計算並明示覆蓋。休市跑出同一行情日期時顯示「無新行情」，不得把行情日期改為執行日期。格式、數值非有限、重複日期、非正價格、調整異常須有驗證或錯誤狀態。

## 管理者手動更新

- 公開訪客只能讀取圖表。管理路由及 API 使用 Cloudflare Access 保護，只允許管理者信箱。
- Pages Function 驗證 Access JWT 的簽章、issuer、audience、期限與允許信箱；缺少設定一律拒絕，不能只信任 email header，也不能只隱藏按鈕。
- POST 端點檢查同源 Origin，使用伺服器端 GitHub 細粒度 Token 觸發 workflow_dispatch；GET 狀態端點讀取執行狀態。GitHub Token 限此儲存庫 Actions 讀寫，不送到前端或記錄日誌。
- 按鈕顯示等待、更新中、成功、無新行情、失敗、配額不足。重複點擊不重複啟動下載。管理者設定不完整時按鈕停用並清楚提示，不能假裝已觸發。

## 設定與交付

GitHub 既有 Secrets：CLOUDFLARE_API_TOKEN、CLOUDFLARE_ACCOUNT_ID。新增行情 Secret：TWELVE_DATA_API_KEY。Cloudflare 伺服器端設定包括 GitHub Actions 觸發 Token、Access issuer/audience 與管理者信箱。建立 Pages 專案名稱採 sector-rotation（若已被帳戶使用需確認現有專案，不覆蓋）。

交付前需有實際 provider smoke test，確認免費帳戶可取 SPY、代表性股票與所需歷史範圍；不能只根據方案文字宣稱已串接成功。金鑰只在 GitHub Secrets 時，由使用者帳戶內 Actions 執行測試，不設法讀回 Secret。

## 驗證

- Python 測試覆蓋比值報酬、逐日複利、週頻暖機、象限邊界、休市重跑、缺值、歷史不足、限流與配額、同一工作恢復。
- 管理 API 測試覆蓋未登入/偽造及過期 JWT、錯誤 audience、跨來源 POST、重複觸發與 GitHub 錯誤。
